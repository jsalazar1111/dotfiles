# Proposal Template Structure

This reference maps each slide in `assets/proposal-template.pptx` to its purpose, the data source that should populate it, and the placeholder content to replace.

## Template Overview

34 slides organized into these sections:

| Slides | Section | Primary Data Source |
|--------|---------|-------------------|
| 1 | Title/Cover | Customer name, date |
| 2 | Agenda | Static (customize section names if needed) |
| 3 | Executive Summary | SOW + discovery + customer research |
| 4 | Your Presenters | User input (sales team names/titles) |
| 5-8 | What We Heard | Discovery transcripts + SOW |
| 9-12 | Solution Overview | SOW (scope, architecture, solution mapping) |
| 13 | Our Assumptions | SOW (assumptions & out-of-scope) |
| 14-17 | Our Approach | SOW (methodology, roadmap, project plan) |
| 18 | Risk Mitigation | SOW + standard Plative risks |
| 19 | Requirements Traceability | Optional, may remove |
| 20 | Program Team Roles | SOW (team structure) |
| 21-22 | Communication Cadence | Standard Plative cadences (customize if SOW specifies) |
| 23-26 | Why Plative | Standard boilerplate, keep as-is |
| 27-31 | Investment Summary | SOW (pricing, hours, rate card, infrastructure fee) |
| 32-33 | Mutual Success Plan | User input (deal timeline milestones) |
| 34 | Closing | Static (Plative logo) |

---

## Slide-by-Slide Detail

### Slide 1: Title Cover
- **Replace:** `{{date}}` with proposal date
- **Replace:** "Customer logo here" with customer name (or logo if provided)
- **Keep:** "Empowering Your Next Competitive Advantage" headline
- **Keep:** "Solution proposal prepared for:" subtext

### Slide 2: Agenda
- **Keep structure as-is.** The 6 agenda items map to the proposal sections.
- **Customize** subtitles under each agenda item if the project focus differs.

### Slide 3: Executive Summary
This is the most important slide. It has four quadrants:
- **Summary** (top-left): 2-3 sentence executive overview of what we're doing and why
- **Target Business Outcomes** (top-right): 3-4 outcome boxes
- **What We Found** (bottom-left table): Key findings/pain points from discovery
- **What We're Recommending** (middle table): Solution recommendations
- **Benefits You'll Realize** (bottom-right table): Quantified benefits

**Data sources:** SOW scope + discovery notes + customer research

### Slide 4: Your Presenters
- **Replace** with sales team members who will present
- **Ask user** for names, titles, and headshots if available

### Slide 5: Section Divider - "What We Heard"
- **Keep as-is** (mountain background divider)

### Slide 6: What We Heard From You
- **Replace** pull quotes with actual stakeholder quotes from discovery transcripts
- **Replace** `{{name}}` and `{{title}}` with actual stakeholder names/titles
- If no transcripts available, synthesize key pain points as attributed quotes

### Slide 7: Your Business Imperatives
- **Replace** business challenges with 3 challenges from SOW/discovery
- **Map** each challenge to target outcomes and impact
- Use the "YOUR GOALS -> TARGET OUTCOMES -> IMPACT" flow

### Slide 8: Our Assessment Of Your Capabilities
- **Customize** the capability matrix based on SOW scope areas
- **Color-code:** Green = Functional/Mature, Yellow = Need Improvement, Red = Large Gap
- **Adjust** the process areas to match the customer's actual capabilities

### Slide 9: Section Divider - "Solution Overview"
- **Keep as-is**

### Slide 10: Solution Overview
- **Replace** with actual solution components from SOW
- Map features to business value in the two-column layout
- Include AI opportunities if relevant

### Slide 11: Solution Mapping
- **Replace** the Problem Statement / Solution Area / Business Impact table
- Pull problem statements from SOW findings
- Map each to the solution area and quantified business impact

### Slide 12: Technical Solution Overview
- **Replace** with actual architecture diagram description from SOW
- List core systems, modules, and integrations

### Slide 13: Our Assumptions
- **Replace** with actual assumptions from SOW
- Organize by category (Entities, Process Areas, Integrations, Operational, Billing, Technical)

### Slide 14: Section Divider - "Our Approach"
- **Keep as-is**

### Slide 15: Transform Methodology
- **Keep as-is** (standard Plative methodology: Discovery > Design > Build > Test > Enable > Deploy > Support)

### Slide 16: Project Roadmap
- **Replace** timeline with actual project dates from SOW
- **Replace** milestone dates and phase descriptions
- **Replace** release/sprint content with actual deliverables

### Slide 17: Project Plan
- **Replace** with actual week-by-week project plan from SOW
- Map deliverables to timeline bars
- Update milestone markers

### Slide 18: Identifying and Mitigating Risk
- **Keep standard risk categories** (Schedule, Scope, Resource, Change Mgmt, Budget)
- **Customize** specific risks and mitigations based on SOW/project context
- Add project-specific risks if identified in discovery

### Slide 19: Requirements Traceability
- **Optional.** Include if SOW references traceability requirements. Otherwise, consider removing.

### Slide 20: Program Team Roles
- **Customize** role list based on SOW team structure
- **Remove** roles not relevant to this project (e.g., UX Design if not in scope)
- **Add** any project-specific roles from SOW

### Slide 21: Our Communication Cadence
- **Keep mostly standard.** Adjust meeting frequencies if SOW specifies different cadence.
- Update participant names if known.

### Slide 22: Client Alignment Framework
- **Keep mostly standard.** This is Plative's governance framework.

### Slide 23-26: Why Plative (boilerplate)
- **Keep as-is.** These are standard Plative capability slides.
- **Slide 24 (By The Numbers):** Update XX placeholders with current Plative stats if available.

### Slide 27: Section Divider - "Investment Summary"
- **Keep as-is**

### Slide 28: Investment Summary
- **Replace** deliverables table with actual SOW line items, hours, and costs
- **Replace** Project Economics box with actual totals
- **Replace** Post-Project Managed Services if applicable

### Slide 29: Program Allocation
- **Replace** quarterly allocation with actual numbers from SOW
- If SOW uses blended rates, populate accordingly. Otherwise, may remove this slide.

### Slide 30: Rate Card
- **Replace** with actual rate card from SOW
- Include all roles, rates, hours, and totals

### Slide 31: All Project Infrastructure, One Flat Fee
- **Replace** project total and infrastructure fee with actual numbers
- Keep the SaaS tools/IP description standard

### Slide 32-33: Mutual Success Plan
- **Replace** milestone table with actual deal milestones
- **Ask user** for key dates: scoping, proposal, contracts, kickoff

### Slide 34: Closing
- **Keep as-is** (Plative logo)

## Slides That May Be Removed

Depending on project scope, these slides may not be needed:
- **Slide 8 (Capability Assessment):** Only if a formal assessment was done
- **Slide 12 (Technical Solution Overview):** Only if architecture diagram is available
- **Slide 19 (Requirements Traceability):** Only if relevant
- **Slide 29 (Program Allocation):** Only if using blended rates

## Slides That May Need Duplication

- **Slide 10-11 (Solution Overview/Mapping):** May need multiple slides if solution is complex
- **Slide 16 (Roadmap):** May need multiple if multi-phase/multi-year
